# UX/UI, дизайн-система и состояния компонентов

## 1. Общие принципы

- Интерфейс должен быть пригоден для ежедневной многочасовой работы.
- Минимальный размер основного текста — 13 px; служебного текста — 11 px.
- Размер кликабельной области на desktop — не менее 32×32 px, на touch — 44×44 px.
- Плотность не должна достигаться уменьшением текста до нечитаемого размера.
- Любое изменение должно иметь видимую обратную связь.
- Цвет не должен быть единственным способом передачи состояния.
- Все интерактивные элементы доступны с клавиатуры.
- Соответствие WCAG 2.2 AA является обязательным.

## 2. Токены дизайн-системы

Дизайн-система должна определять:

- палитру light и dark themes;
- семантические цвета `primary`, `success`, `warning`, `danger`, `info`, `neutral`;
- типографическую шкалу;
- spacing scale;
- размеры и радиусы;
- тени;
- breakpoints;
- z-index scale;
- transition durations;
- chart palette;
- цвета пользователей для presence и курсоров.

Компоненты не должны использовать произвольные цвета и размеры вне токенов без обоснования.

## 3. Темы

- Light theme обязательна.
- Dark theme обязательна для целевой версии.
- Доступна системная тема.
- Пользовательская тема хранится на аккаунте.
- Графики и редактор должны корректно менять палитру без перезагрузки.
- Экспортируемый PDF использует отдельную печатную тему.

## 4. Плотность

Поддерживаются режимы:

- `comfortable`;
- `compact`.

Режим влияет на высоту строк, padding и число вторичных подписей, но не уменьшает текст ниже установленного минимума.

## 5. Базовые состояния любого компонента

Каждый интерактивный компонент должен иметь:

- default;
- hover;
- focus-visible;
- active/pressed;
- selected;
- disabled;
- readonly;
- loading;
- success;
- warning;
- error;
- permission-restricted;
- plan-restricted.

Focus ring не скрывается. Disabled-элемент не должен использоваться для передачи причины без tooltip или пояснения.

## 6. Кнопки

Варианты:

- primary;
- secondary;
- tertiary;
- ghost;
- danger;
- icon;
- split button.

Требования:

- во время отправки кнопка блокирует повторный submit и показывает progress;
- текст не должен исчезать, если это вызывает изменение ширины;
- опасное действие не должно визуально выглядеть как primary;
- icon-only кнопка имеет `aria-label` и tooltip;
- destructive confirmation содержит точный объект и последствия;
- повторяемые безопасные действия могут иметь undo вместо confirm.

## 7. Поля и формы

Состояния поля:

- empty;
- filled;
- focused;
- valid;
- invalid;
- validating;
- disabled;
- readonly;
- autofilled;
- server-error.

Правила:

- label сохраняется при вводе;
- placeholder не заменяет label;
- обязательность отмечается текстом или символом с легендой;
- ошибка показывается рядом с полем и в summary формы;
- серверная ошибка связывается с полем, если возможно;
- при submit фокус переходит к первой ошибке;
- несохранённые изменения защищаются navigation guard;
- автосохранение показывает `Сохранение`, `Сохранено`, `Ошибка сохранения`, `Офлайн`.

## 8. Select, autocomplete и фильтры

- Для списков более 20 элементов используется поиск.
- Для очень больших справочников используется серверный autocomplete.
- Выбранные значения показываются chips.
- Фильтр различает «не задано», «пусто», `0` и `false`.
- Активные фильтры видны над результатами.
- Доступно «Сбросить всё».
- Сложные фильтры можно сохранить как view.
- Сохранённый view содержит колонки, сортировку, фильтры, группировку и плотность.
- Выпадающий слой составного select внутри modal/dialog принадлежит overlay-root
  этой модалки: он выше backdrop, не обрезается scroll-контейнером формы и
  остаётся доступен с клавиатуры и указателя.
- В мастерах съёма позиций, частотности, ИИ-ответов и кластеризации используется
  единый выбор области операции. Режим «Конкретные запросы» читает запросы
  cursor-страницами и автоматически подгружает следующую страницу при
  прокрутке; ручная offset-пагинация и предварительная загрузка всего проекта
  не допускаются. Состояние выбранных строк сохраняется между страницами и
  поисковыми запросами.
- На desktop список конкретных запросов занимает доступную высоту колонки, а
  дерево папок растёт по содержимому только до доступного максимума: небольшое
  дерево не растягивает строки и не создаёт искусственно высокое окно. Оба
  списка можно изменить по высоте вертикальным resize; это не сдвигает footer
  модалки и не обрезает действия. На узком экране колонки складываются, окно
  получает ограниченную высоту viewport и собственную прокрутку без
  недоступного resize-handle.
- Мастера позиций, частотности, ИИ-ответов и кластеризации используют три
  самостоятельные колонки: источник, параметры и охват. При недостаточной
  ширине они переходят в последовательный одноколоночный поток.
- Project select во всех разделах использует один renderer и общий серверный
  порядок. Разрешённые строки имеют drag handle и клавиатурную альтернативу
  `Alt+ArrowUp/ArrowDown`; drop indicator однозначно показывает вставку до или
  после строки. Во время сохранения список остаётся стабильным и сообщает
  «Сохранение порядка», после успеха — «Порядок сохранён». Ошибка возвращает
  предыдущий порядок и остаётся доступной через live region; optimistic
  conflict перечитывает authoritative список. Footer создания проекта не
  перекрывает строки и отражает permission/plan-restricted причину.

## 9. Таблицы данных

### 9.1. Общие требования

- Виртуализация строк обязательна для более 500 отображаемых строк.
- Виртуализация колонок применяется для широких таблиц.
- Поддерживаются cursor pagination и infinite scroll; offset pagination запрещена для больших наборов. Основные списки приложения автоматически запрашивают следующую cursor-страницу при приближении к концу, сохраняя кнопку как доступный retry fallback там, где ошибка требует явного повтора.
- Служебная область слева имеет неизменный порядок и ширину: позиция строки,
  затем checkbox выбора, затем пользовательские колонки. Позиция считается в
  текущем серверном порядке с учётом виртуализированного смещения.
- Для таблицы с настраиваемыми ширинами итоговая ширина равна точной сумме
  служебных и пользовательских колонок. Свободное место viewport не
  перераспределяется между колонками: resize изменяет только выбранную колонку,
  а открытие sidebar не вызывает reflow или скачок соседних колонок.
- Панель колонок на desktop является overlay над неизменным viewport таблицы.
  Её открытие и закрытие сохраняют ширину viewport, горизонтальный scroll,
  заголовки и уже загруженные значения; presentation-state панели не является
  причиной HTTP-перезагрузки данных.
- Есть явный горизонтальный scrollbar.
- Заголовок таблицы закреплён.
- Состояние сортировки и фильтров отражается в URL или сохранённом view.
- Обычные и динамические географические колонки позиции, найденного URL и даты
  используют один renderer. URL имеет единый цвет и переносится максимум на две
  строки; визуальный вес позиции и обозначение изменения не зависят от типа
  колонки.
- Cursor-запрос основной таблицы содержит точный список видимых metric и
  географических колонок. Их значения приходят в ответе той же страницы;
  последовательный browser-запрос для заполнения уже показанных строк запрещён.
  Скрытые frequency, position, AI и SERP-проекции не читаются сервером;
  настройка индикатора query-ячейки сама по себе не расширяет чтение.
- При открытии проекта таблица сначала разрешает сохранённый layout, затем
  отправляет одну cursor-страницу с его колонками; предварительный запрос с
  default layout и последующий дублирующий запрос запрещены.
- Таблица доступна с клавиатуры.

### 9.2. Состояния таблицы

- `initial-loading` — skeleton без пустого сообщения;
- `refreshing` — текущие данные остаются, показывается ненавязчивый progress;
  ошибка фонового обновления переводит их в degraded-state, но не заменяет
  пригодные значения символом ошибки;
- `loaded`;
- `empty-project` — нет данных, CTA импорта/создания;
- `empty-filter` — данные есть, но фильтр ничего не нашёл;
- `partial-data` — часть колонок ещё вычисляется;
- `stale` — данные устарели, видна дата и действие обновления;
- `offline` — локальный просмотр, изменение ограничено;
- `recoverable-error` — retry без потери фильтров;
- `fatal-error` — correlation ID и переход в поддержку;
- `permission-restricted`;
- `bulk-running` — виден job и scope;
- `conflict` — строка изменилась другим пользователем;
- `deleted-remotely` — строка удалена или перемещена коллегой.

### 9.3. Выделение

- Все checkbox-контролы имеют квадратную геометрию `aspect-ratio: 1 / 1` и не
  растягиваются родительским flex/grid-контейнером; radio остаются круглыми.
- Чекбокс строки выбирает строку для массовых операций; визуальное выделение
  строк является отдельным состоянием и не изменяет checkbox.
- Обычный клик визуально выделяет одну строку, Shift выделяет диапазон, а
  Ctrl/Cmd+клик добавляет или убирает отдельную строку без сброса остальных.
- Ctrl/Cmd+A после фокуса таблицы визуально выделяет весь текущий filter scope
  и не выбирает строки для массовых операций. Главный checkbox по-прежнему
  выбирает весь filter scope.
- Контекстное меню строки отдельно копирует выбранные checkbox-строки и
  визуально выделенные строки, сохраняя текущий порядок таблицы.
- `Выбрать все на странице` отличается от `Выбрать все по фильтру`.
- При выборе всех по фильтру сервер хранит selection expression, а не миллионы ID в клиенте.
- Изменение фильтра при активном выборе требует подтверждения либо сбрасывает выбор по заранее указанному правилу.
- Bulk bar показывает точное количество или формулировку «Все N по фильтру».

### 9.4. Inline editing

- Enter начинает редактирование.
- Escape отменяет локальное изменение.
- Tab сохраняет и переходит к следующей ячейке.
- Во время сохранения ячейка имеет pending-state.
- Ошибка сохраняет введённое значение.
- Конфликт показывает исходное, пользовательское и серверное значение.
- Активная ячейка другого пользователя подсвечивается его цветом.
- Presence не блокирует редактирование, кроме явно эксклюзивных операций.

## 10. Деревья групп и страниц

Состояния:

- collapsed/expanded;
- selected;
- partially-selected;
- drag-target;
- loading-children;
- empty;
- locked-by-job;
- renamed-remotely.

Drag-and-drop должен иметь клавиатурную альтернативу «Переместить в…». Перемещение большого поддерева выполняется асинхронно.

Правый клик по строке папки открывает только контекстное меню и не изменяет
текущую открытую папку или состояние её раскрытия. Для папки внутри текущей
мультивыборки сохраняется общий batch scope; иначе команды относятся только к
строке под курсором.
Active и selected состояния папки не меняют насыщенность названия: различие
передают фон, контур, направляющая и цвет текста.

Каждый видимый уровень вложенности в основном дереве, modal picker и дереве
области операции отмечается спокойной вертикальной направляющей в отступе
строки. Направляющие не занимают место контента, не перехватывают pointer
events и усиливаются только в hover/selected/active состояниях. Плоский select
не используется для выбора иерархической папки. Закрытое поле picker показывает
название выбранной папки первой строкой и её полный путь второй строкой; служебные
варианты без иерархии остаются однострочными. Высота trigger совпадает с соседними
полями: внутри остаются цветовой маркер, название, путь и счётчик запросов справа,
но не дублирующая иконка папки. Переполненный путь циклически прокручивается, а при
`prefers-reduced-motion` остаётся статично обрезанным.

## 11. Графики

- У каждого графика есть заголовок, период, единицы и источник.
- Tooltip доступен клавиатурой.
- Можно отключать серии.
- Нет данных, нулевые данные и ошибка не смешиваются.
- Частичные данные обозначаются разрывом или штриховкой.
- На временной шкале поддерживаются annotations.
- Пользователь может открыть таблицу исходных данных.
- Экспорт изображения и CSV учитывает текущие фильтры.
- Цвета серий сохраняются между экранами.

## 12. Метрики и score

- Score допускается только при опубликованной формуле.
- Tooltip объясняет составляющие и вес.
- Изменение score связывается с причинами.
- Прогноз трафика показывает модель CTR, частотность, позицию, сезонность и диапазон неопределённости.
- Нельзя отображать прогноз как гарантированный результат.

## 13. Модальные окна и drawers

- Modal имеет `role=dialog`, `aria-modal`, heading и description.
- Фокус устанавливается в modal и возвращается инициатору.
- Focus trap обязателен.
- Escape закрывает окно, кроме критической необратимой операции.
- Клик по backdrop не должен закрывать окно с несохранёнными данными без подтверждения.
- One-time secret API-ключа показывается в отдельной modal. До успешного
  clipboard copy или пользовательского события `copy` Escape, backdrop,
  крестик и финальная кнопка не закрывают окно; после копирования все обычные
  способы закрытия снова доступны.
- Длинные пошаговые процессы открываются как отдельная страница или fullscreen wizard.
- Drawer используется для деталей, очереди и комментариев, но не для сложной многошаговой настройки.
- Остановка фонового сбора из карточки или detail modal всегда требует
  отдельной warning-modal. Default focus остаётся на безопасном действии
  продолжения; destructive request отправляется только после явного
  подтверждения.

## 14. Уведомления и feedback

### Toast

Используется для краткого подтверждения. Не должен содержать единственную копию важной ошибки.
Стек закрепляется ниже app header и safe-area, ограничивается dynamic viewport
и прокручивается внутри себя; ни первый, ни последний toast не могут оказаться
за границей экрана. Фон и текст имеют явный контраст для info/success/warning/
danger, независимо от цвета иконки.

### Inline alert

Используется для ошибок формы, лимитов, истёкших токенов и частичных данных.

### Notification center

Содержит постоянную историю уведомлений, фильтры, read/unread и deep links.

### Progress

- determinate для известного объёма;
- indeterminate для подготовки;
- показывает обработано/всего, ETA и этап;
- после завершения содержит ссылку на результат.

### Оценка готовности съёма позиций

Панель оценки доступна из tracking context и не должна выглядеть как
фактический запуск провайдера. Поддерживаются состояния:

- `idle`;
- `calculating`;
- `ready`;
- `blocked` со всеми причинами;
- `expired`;
- `offline`;
- `recoverable-error` с безопасным повтором;
- `conflict` с явным новым расчётом;
- `permission-restricted`.

Неоднозначный сетевой повтор использует тот же `Idempotency-Key`, а явный
пересчёт — новый. Уже полученная оценка остаётся доступной в read-only и
архивном проекте. Интерфейс отдельно показывает точный или ограниченный
объём, число задач и минимальных API-вызовов, неизвестные provider limits и
duration, квоту, свежесть credential, retention и срок действия. Значение
`1001` отображается как «более 1 000», а неизвестные лимит, длительность или
polling не подменяются нулём. Пока execution gate закрыт, действие запуска
остаётся недоступным с понятным объяснением причины.

Форма ручного съёма открывается с рабочими значениями `Яндекс`, `Москва
(213)`, `Live`, `Топ-50` и выбирает первый доступный маршрут, способный
выполнить такую глубину. Все активные подключения текущей effective route
показываются явно. При выборе Arsenkin для Яндекса интерфейс честно
переключает глубину на поддерживаемый `Топ-30` и объясняет ограничение.

## 15. Загрузка файлов

Состояния uploader:

- idle;
- drag-over;
- validating-client;
- awaiting-upload-session;
- uploading;
- paused;
- reconnecting;
- uploaded;
- server-validating;
- mapping-required;
- importing;
- partial-success;
- completed;
- cancelled;
- failed-retryable;
- failed-final;
- expired-upload.

Требования:

- resumable multipart upload для крупных файлов;
- checksum;
- защита от повторной загрузки;
- pause/resume;
- отмена;
- фоноваая обработка после закрытия страницы;
- уведомление по завершении;
- файл проходит антивирусную проверку;
- исходный файл хранится по retention policy.

## 16. Пустые состояния

Каждое пустое состояние отвечает на вопросы:

- почему здесь пусто;
- что можно сделать;
- требуются ли интеграции или права;
- есть ли пример или шаблон.

Пустое состояние нового проекта отличается от пустого результата фильтра.

## 17. Ошибки

Пользовательское сообщение не должно показывать stack trace, токены или сырой ответ провайдера.

Ошибка содержит:

- понятное описание;
- что произошло с данными;
- можно ли повторить;
- рекомендованное действие;
- correlation ID;
- ссылку на детали задания, если ошибка асинхронная.

## 18. Offline и нестабильная сеть

- Интерфейс показывает потерю соединения.
- Просмотр уже загруженных данных остаётся доступен.
- Небезопасные изменения не имитируют успешное сохранение.
- Допускается локальная очередь только для идемпотентных изменений.
- После reconnect выполняется refetch версий.
- Совместные документы могут использовать Yjs offline persistence.

## 19. Адаптивность

### Desktop ≥ 1280

Полный функционал, широкие таблицы и многоколонные dashboard.

### Laptop 1024–1279

Сворачиваемая навигация, сокращённые вторичные подписи, горизонтальный scroll таблиц.

## 20. Состояния страниц

Каждая страница обязана иметь спецификацию:

- title и breadcrumbs;
- права доступа;
- initial loading;
- loaded;
- empty;
- empty by filter;
- partial;
- stale;
- recoverable error;
- fatal error;
- forbidden;
- archived/read-only;
- offline;
- deleted/not found;
- plan restriction;
- mobile behavior.

Эти состояния включаются в критерии приёмки каждой user story.

### 20.1. Единая навигация настроек

Все account-, workspace- и project-настройки используют один левый settings
rail на desktop и тот же rail как горизонтальный overflow-nav на узких
экранах. Обзор не дублирует навигацию верхними вкладками. В обзорной карточке
переход выполняется по всей шапке с `focus-visible`; отдельная нижняя CTA не
дублируется. Scroll surface имеет нижний safe-area отступ на каждой странице.
В нижнем usage-блоке основного sidebar денежный показатель называется
«Баланс»; отдельная строка «Управлять тарифом и балансом» не дублирует ссылку
шапки тарифа.

Активные сессии, приглашение участника и project access editor обязаны
перестраиваться без горизонтального overflow: metadata меняется с трёх колонок
на две и одну, а mutation controls получают полный touch-width на телефоне.

### 20.2. Главный экран проекта

Первая строка содержит пять живых KPI: число активных запросов, число
отслеживаемых запросов, среднюю текущую позицию и число запросов в Топ-10 и
Топ-30. Средняя и накопительные TOP-счётчики считаются один раз на каждый
active keyword, имеющий найденную позицию; отсутствующие позиции в знаменатель
не входят. Все позиционные KPI и график относятся к одному точному сочетанию
поисковика, города, языка и устройства; общей строки «Все города и устройства»
в selector нет. Сразу под KPI находится полноширинный график количества
отслеживаемых запросов в Топ-3/5/10/30/50. Над графиком расположены независимые
кнопки периода `7 дней | 30 дней | 90 дней | всё время` и включения серий;
хотя бы одна серия всегда остаётся активной. Начальный период — 30 дней, а
визуальная проекция ограничена 30 равномерно выбранными календарными днями,
включая края интервала; API отдаёт до 100 последних дневных точек. Все съёмы
одного UTC-дня объединяются; состояние каждого keyword изменяется его последним
снимком дня и переносится на последующие дни съёма остальных запросов того же
среза. Поэтому
частичная проверка не обнуляет ключи, которые в этот день не снимались, а
повторные съёмы не умножают число запросов.
Tooltip изначально закрыт; hover и keyboard focus показывают дату и значения
всех включённых серий.
SVG-проекция следует фактической ширине контейнера: подписи шкалы Y остаются
у левого края plot area, а увеличенный tooltip не теряет читаемость на
широких и узких экранах.
Отдельная кнопка «Неотслеживаемые» меняет серверный scope графика. По умолчанию
она выключена, и TOP-счётчики включают только active keywords с
`isTracked=true`; во включённом состоянии API пересчитывает каждый срез по
всем active keywords, включая текущие неотслеживаемые. Клиент не смешивает и
не пересчитывает эти выборки локально, показывает ожидание и отдельную ошибку
повторной загрузки, а пустой tracked-scope сохраняет доступ к переключателю.
Начальный точный срез берётся из общей настройки экрана «Позиции» для текущих
user/project. Если она ещё не задана или недоступна, выбирается desktop-срез
города проекта, затем первый доступный срез. Выбор на dashboard сохраняется в
ту же настройку и применяется при следующем открытии «Позиций» и обзора.
Рядом с быстрыми периодами находится custom range. Он не использует
браузерный `input[type=date]`: первый клик выбирает один календарный день и
одновременно начинает диапазон, второй клик завершает диапазон независимо от
направления выбора. Доступны пресеты `Сегодня`, `Неделя`, `Месяц` и
`3 месяца`; выбранные границы выводятся компактно и не являются отдельными
кнопками редактирования. Пользователь переключает месяцы и применяет диапазон
явной кнопкой. Доступный диапазон истории выводится в header. Недоступные раньше
первого и позже последнего загруженного дня даты выключены. На desktop
календарь показывает два соседних месяца в popover, на телефоне — один месяц
в bottom sheet; Escape, клик снаружи и повторный клик по trigger закрывают
черновик без применения. Custom range также ограничивается 30 равномерными
точками и честно сохраняет пустое состояние выбранного периода.
Пустой выбранный период не изображается нулевыми значениями и предлагает
расширить период. Карточки «Проблемы аудита» и «Техническое состояние»,
а также быстрые действия «Запустить аудит» и «Собрать конкурентов» на главном
экране не показываются. График позиций и последние операции остаются.
На телефонах все блоки нижней части обзора, включая «Последние операции» и
«Работа проекта», образуют одну колонку без минимальной desktop-ширины и не
могут накладываться друг на друга. Фиксированная нижняя навигация не меняет
ширину карточек и не закрывает доступный scroll content. Обе строки фильтров
графика прокручиваются только внутри себя и не расширяют страницу; сам plot
следует доступной ширине карточки, а крайний tooltip прижимается к границе plot
без обрезания и горизонтального overflow.

### 20.3. Фавиконы проектов

Переключатель проектов и каталог «Настройки → Проекты» читают изображение
через same-origin permission-scoped endpoint. Пользовательский upload имеет
приоритет; иначе сервер bounded-поиском проверяет HTML icon links, manifest и
стандартные favicon-пути, выбирая SVG или наиболее качественный raster.
Поддерживаются безопасные SVG, PNG, JPEG, WebP, ICO, GIF и AVIF до 512 KiB.
Пока изображение не загружено, layout сохраняет стабильный слот; ошибка или
отсутствие файла не создаёт broken-image/letter placeholder.

### 20.4. Tenant navigation и дерево семантики

Основной левый sidebar плавно сворачивается до icon rail и сохраняет это
presentation-only предпочтение в `localStorage` и несекретной cookie, не меняя
workspace/project context. Общий protected layout сохраняет `AppShell` при
клиентской навигации; активные пункты определяются по pathname. Выбранные
элементы tenant dropdown обозначаются фоном и обводкой без отдельной галочки.
Workspace показывает загруженный avatar с буквенным fallback.
Project selector в sidebar и заголовке семантики использует одинаковые строки
с logo; иконка остаётся видимой и в закрытом выбранном значении. Ненулевой
счётчик активных операций показывается компактным badge со spinner. Такой же
селектор находится в заголовках операций, заметок и карты страниц. Кнопка
«Операции» в command bar семантики также показывает badge. Все эти consumers
читают одну tenant-scoped карту активности из persistent `AppShell`: она
обновляется по таймеру, focus/visibility и событию после mutation, а отсутствие
проекта в успешной authoritative projection означает ноль. При временной
ошибке сохраняется последнее подтверждённое значение; при нуле индикатор скрыт.
Порядок этих строк является общей workspace-настройкой: разрешённый drag или
клавиатурное перемещение сохраняется на сервере и после перехода в другой
раздел воспроизводится без локальной сортировки. Действие «Создать проект» в
нижней части того же popup открывает существующий project wizard и показывает
текущее использование тарифной capacity.

В дереве семантики корневые пользовательские папки остаются sticky внутри
собственного scroll container. «Все запросы», «Без группы» и «Корзина» имеют
семантические иконки; две системные папки не входят в число пользовательских
групп. Диалог новой папки после открытия переводит фокус в «Названия папок»;
это обычное многострочное поле, где каждая непустая строка создаёт отдельную
папку, а счётчик рядом показывает объём списка относительно лимита 200.

## 21. Настройки источников проекта

Маршрут `/app/projects/{projectId}/settings/integrations` использует точный
project deep link, а не только workspace из старого cookie. Для первого
рабочего среза экран настраивает `SERP_RANK_TRACKING`; contract и backend
остаются capability-based.

Экран содержит:

- heading и project settings tabs «Источники проекта» / «Уведомления проекта»;
- один binding с provider/label/status и честной стоимостью BYOK у самого
  провайдера;
- недоступные credentials с причиной, но без full secret, masked hint и
  provider metadata;
- ссылку на workspace-экран управления ключами;
- заблокированные пояснения для platform key, fallback и budget без ложных
  интерактивных controls;
- sticky save bar с dirty/version state.

Обязательные состояния:

- initial loading с `aria-busy`;
- recoverable load error и retry без потери уже загруженного state;
- пустой список credentials и отсутствие подходящих `ACTIVE BYOK_API_KEY`;
- bounded список более 500 credentials с явным сообщением о неполной выдаче
  и ссылкой на workspace-экран управления подключениями;
- готовый, выключенный, pending, unavailable и capability-mismatch binding;
- billing read-only, archived project и view-without-update;
- dirty, busy, success и offline без локальной mutation queue;
- `412 VERSION_CONFLICT`: пользовательский draft сохраняется, authoritative
  binding перечитывается, пользователь явно принимает серверную версию либо
  повторяет поверх новой версии;
- `401` ведёт через refresh с исходным `returnTo`, `402` сохраняет read-only
  просмотр, `403` очищает credential options, `404` не раскрывает существование
  чужого проекта;
- mobile: одна колонка, touch target не менее 44 px и отсутствие document
  overflow.

Create использует стабильный `Idempotency-Key` до смены payload или успешного
ответа. Поскольку точный replay может вернуть immutable create snapshot после
чужого PATCH, Web после POST перечитывает aggregate и принимает только текущую
server revision. Update отправляет текущий `If-Match`; WebSocket может только
ускорить refetch, но не заменяет authoritative HTTP response/version.

## 28. Единая геометрия modal и панелей данных

Все диалоги используют `SemanticModal`: единые header/footer, размер заголовка,
описание, close action, focus trap и mobile sheet. Формы получают обычный
внутренний отступ. На desktop общий ритм ограничен `16 px` для body и
горизонтальных полей header/footer; вложенная форма не создаёт вторую белую
sticky-плашку действий внутри цветной панели. История, выдача и другие плотные read-only данные используют
`bodyLayout="edge"`: строки разделяются линиями на всю ширину без вложенной
карточки с дополнительными боковыми полями и повторными крупными скруглениями.

Сайдбар запроса имеет одну шкалу заголовков и значений и изменяемую ширину
`300..620 px`. Ручка находится на границе таблицы и правого инспектора и
визуально совпадает с ручкой дерева групп. Ширина сохраняется локально отдельно
для каждого пользователя и проекта, поддерживает pointer, клавиши
стрелок/Home/End и двойной клик для сброса. График истории измеряет доступную
ширину панели и расширяет plot area вместе с ней. На узком экране панель
остаётся viewport-safe, а resizer скрывается.

Блок позиций сначала восстанавливает последний выбранный dimension отдельно для
пользователя, проекта и текущего представления; если у открытого ключа такого
среза нет, выбирает самый свежий реально измеренный. Поэтому основной график
виден сразу. В trigger и каждой строке раскрытого списка первой строкой показаны
поисковик, город и устройство, второй — дата, provider и источник, справа —
позиция и изменение. Явно выбранный dimension хранится локально по
user/project/view и повторно применяется при открытии любого другого ключа.
Автоматический fallback для ключа без этого среза меняет только текущий показ и
не перезаписывает предпочтение пользователя. Срезы,
существующие в проекте, но не измеренные для открытого ключа, остаются в списке
disabled и не входят в числовой badge заголовка. Пустой блок ИИ-позиций не
рендерится до первого сохранённого ИИ-съёма.

Иконки заметки и несовпадения URL являются кнопками. Заметка открывает modal с
загрузкой полного текста, optimistic version, явным сохранением и удалением.
URL modal объединяет целевой URL и найденные страницы выбранного точного
среза. Общий compact selector переключает поисковик, город и устройство и
перезагружает URL/SERP только этого dimension; сохранённые правила объединения
срезов применяются до отображения. При открытии индикатора нецелевого URL
selector содержит только срезы с фактическим несовпадением и сразу выбирает
первый такой срез; корректные URL в эту modal не попадают. Верхний повторный
список найденных URL не выводится: modal оставляет только страницы домена из
сохранённого SERP с их исходными номерами позиций. Флаг «Показать различия»
выделяет отличающиеся части URL непосредственно в SERP-строках без изменения
ссылок, ширины строки и начертания домена; домен остаётся жирным до и после
переключения.

Экран позиций не дублирует название проекта и выбранный dimension над отчётом.
Верхняя строка использует `CustomSelect` для города/поисковика/устройства,
группы и сортировки и общий `CustomDateRangePicker` для периода. KPI имеют
плотную однострочную геометрию; распределение по ТОПам скрыто до нажатия
отдельной кнопки. Вся рабочая область прокручивается по вертикали. Матрица имеет
собственный видимый вертикальный и горизонтальный scroll, sticky header и
подгружает следующую cursor-страницу у нижней границы; поэтому длинный список
ключей остаётся доступным независимо от высоты KPI и раскрытых графиков.
Поисковый `CustomSelect` переводит keyboard-active строку на первый результат
нового запроса и прокручивает список программно только при открытии, изменении
поискового текста или навигации клавиатурой. Обычный wheel/touch scroll не
возвращается к ранее выбранной строке при фоновой перерисовке options.
Первый `Escape` закрывает только открытый `CustomSelect` и не передаётся
родительской модалке либо сайдбару.

В карточке запроса сезонность следует непосредственно за частотностью. Значения
частотности показывают название региона вместо provider-кода и локализованное
«Последние 30 дней». Кнопка истории выдачи расположена под конкурентами,
а рост/падение в option выбора dimension использует те же зелёный и
красный состояния, что таблица семантики. Сезонный график использует штатный
логотип Яндекса и единый tooltip без
переноса даты; footer повторяет значения всех доступных серий выбранного периода.
