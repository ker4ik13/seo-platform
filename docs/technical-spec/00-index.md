# Техническое задание: международная SEO-платформа

Статус: проект целевой версии  
Версия: 1.1-draft
Дата: 28 июля 2026 года  
Рабочее название: «Платформа»  
Язык документа: русский  

## 1. Назначение документа

Этот комплект документов определяет продуктовые, функциональные, UX/UI, архитектурные и эксплуатационные требования к международной SaaS-платформе для SEO-специалистов, агентств, внутренних команд и их клиентов.

ТЗ является основой для:

- проектирования интерфейсов;
- разработки frontend, backend и worker-приложений;
- проектирования PostgreSQL и Prisma-схем;
- разработки интеграций;
- построения маркетингового сайта и CMS;
- разработки внутренней административной панели;
- тестирования и приёмки;
- планирования этапов релиза.

Требования сформулированы для целевого продукта. Фактическая реализация выполняется по этапам, указанным в `16-roadmap-and-acceptance.md`.

## 2. Зафиксированные решения

- Продукт сразу ориентирован на международный рынок.
- Юридическая регистрация оператора на первом этапе — Российская Федерация.
- Первоначальный налоговый статус оператора — плательщик НПД
  (самозанятый); чеки НПД требуются только для успешных платежей ЮKassa.
- Интерфейс и контент поддерживают локализацию; первыми локалями являются `en` и `ru`.
- Единый Next.js web-продукт работает на основном домене: публичный сайт,
  статьи, индексируемый Toolbox и API-документация находятся в публичной
  ветке, приложение — в защищённой ветке `/app`.
- Все маршруты `/app` закрыты от индексации через metadata, HTTP-заголовки и
  `robots.txt`; одной директивы `Disallow` недостаточно.
- Machine API и status page работают на технических поддоменах.
  Административная панель является защищённой веткой `/admin` единого Web.
  Документация API публикуется на основном сайте в `/docs/api`, а
  каноническая OpenAPI-схема доступна также через API gateway.
- Конкретное имя домена и бренд в ТЗ не фиксируются.
- Frontend приложения: Next.js, React, TypeScript.
- Backend: NestJS.
- Основная СУБД: самостоятельно размещаемый PostgreSQL 18.x.
- ORM: Prisma ORM и Prisma Migrate.
- Развёртывание: VPS-серверы под управлением Dokploy.
- Архитектура: ограниченное количество доменных микросервисов, без чрезмерного дробления.
- Очереди: Redis + BullMQ.
- Межсервисные надёжные события: transactional outbox + NATS JetStream.
- Real-time: Socket.IO с Redis adapter; совместные документы — Yjs/Hocuspocus.
- Маркетинговый контент текущей версии — типизированный source единого Web;
  внешний CMS допускается только отдельным ADR при появлении редакционного
  workflow.
- Административная панель приложения: защищённый `/admin` того же Next.js.
- Пользователь может подключать собственные ключи внешних API (BYOK) либо пользоваться системными ключами в рамках тарифа и баланса.
- Первый платёжный провайдер — ЮKassa; платёжный слой остаётся provider-agnostic для последующего подключения международного эквайринга или Merchant of Record.
- Первые коммерческие SEO-коннекторы — Keys.so, Arsenkin Tools и XMLStock.
- Keys.so и Arsenkin Tools запускаются в BYOK-режиме; использование общего ключа платформы допускается только после письменного разрешения или отдельного коммерческого соглашения с провайдером.
- XMLStock запускается в BYOK-режиме и, после согласования developer/partner условий, в режиме системного баланса платформы.
- Импорт из Key Collector включает экспортированные CSV/TSV/XLSX и нативный
  проект `.kc4`. Для `.kc4` сохраняются активные запросы, полная иерархия,
  пустые группы, множественное членство запроса, доступные Wordstat/SERP/KEI
  и пользовательские поля; корзина Key Collector не импортируется.
- Собственные домены агентств не требуются.
- Требуются клиентский режим, гостевые отчёты и white label без custom domains.
- Требуются совместная работа, присутствие, видимые курсоры и выделения ячеек.
- Авторизация: email/password, Google, Яндекс и Telegram; 2FA обязательна как возможность.
- Публичный индексируемый Toolbox и проектный Toolbox используют единый
  capability registry, API-контракты и worker-реализации.
- Базовый публичный API всех SEO-инструментов входит во все платные тарифы.
- Проекты не удаляются автоматически из-за окончания подписки или баланса:
  ограничиваются новые операции, но сохраняются просмотр и допустимый экспорт.
- Агрегированная история хранится без фиксированного продуктового срока, пока
  workspace существует; тяжёлые raw SERP имеют отдельную retention policy.

## 3. Нормативные слова

- **Должен** — обязательное требование.
- **Не должен** — обязательное ограничение.
- **Следует** — рекомендуемое требование, отступление требует архитектурного решения.
- **Может** — необязательная возможность.
- **Целевая версия** — полный продукт, описанный в ТЗ.
- **Первая производственная версия** — набор функций этапов P0–P2.

## 5. Иерархия требований

При противоречии требований применяется следующий приоритет:

1. безопасность и законодательные обязательства;
2. сохранность и изоляция данных арендаторов;
3. явно сформулированное бизнес-правило;
4. функциональное требование экрана или модуля;
5. UX-рекомендация;
6. конкретная библиотека или техническая рекомендация.

Замена указанной библиотеки допустима, если сохраняются контракты, поведение и нефункциональные требования. Замена PostgreSQL, Prisma, Next.js, NestJS или Dokploy требует отдельного архитектурного решения.

## 6. Управление изменениями ТЗ

Каждое значимое изменение оформляется записью:
