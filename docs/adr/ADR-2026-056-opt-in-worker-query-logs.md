# ADR-2026-056: поисковые фразы в логах доверенного воркера только по согласию

- Статус: принято
- Дата: 1 октября 2026 года
- Затронутые области: удалённый worker, Docker Compose, эксплуатация
- API и владение данными не меняются

## Контекст

Оператору нужны понятные логи удалённого узла для диагностики скорости и
сбоев. Текст поисковой фразы — пользовательские данные, а Docker logs могут
храниться дольше самой задачи и быть доступны администраторам машины.
Credential, provider task ID, ticket и полные HTTP URL в логи недопустимы.

## Решение

Агент по умолчанию пишет на русском только тип задачи, провайдера, внутренний
ID задания, момент начала, длительность и безопасный код результата. Он не
утверждает, что результат уже записан в доменную БД: подтверждён только приём
центром. Тексты фраз не пишутся по умолчанию.

На явно доверенном узле оператор может включить `WORKER_LOG_QUERIES=true`.
Тогда агент пишет максимум три фразы на HTTP-задание, каждую ограничивает 160
символами, убирает управляющие символы и маскирует переданный ему API-ключ.
Провайдерские секреты, account ID, signed tickets, provider request ID и
полные payload/URL не выводятся даже при включённом режиме. Docker Compose
ограничивает хранение логов ротацией файлов. Переменная не пересылается центру
и не даёт доступ к фразам другого задания или узла.

## Последствия

Режим с фразами повышает риск локального раскрытия пользовательских данных:
включать его только на доверенном ПК, ограничить доступ к Docker и выключать
после диагностики. Для возврата безопасного поведения достаточно
`WORKER_LOG_QUERIES=false` и пересоздания контейнера; уже записанные строки
живут до ротации логов либо операторской очистки на конкретном узле.
