# ADR-2026-054: шаги фоновых операций через Worker Gateway

- Статус: реализовано на тестовом стенде; production cutover не выполнен
- Дата: 30 сентября 2026 года
- Дополняет ADR-2026-051/052/053; владельцы данных не меняются

Все согласованные типы операций используют общий транспорт небольших шагов:
HTTP провайдера, получение страницы сайта, разбор исходного файла, кодирование
экспорта и антивирусную проверку. Существующий владелец операции в центре
продолжает проверять права, резервировать деньги, управлять отменой и
идемпотентно сохранять результаты в Core SEO. Удалённый узел получает только
материал назначенного шага по исходящему HTTPS. SMTP остаётся в центре.

Jobs хранит `remote_work_tasks` и назначение операции в
`remote_operation_assignments`. SQL проверяет действующий lease исходного
workflow до выдачи шага. Исполнение имеет отдельный одноразовый token;
поздний ответ не перезаписывает уже подтверждённый receipt. Узлы запрашивают
работу одной пачкой раз в пять секунд. Пулы HTTP и CPU ограничиваются
совместно с разрешёнными слотами каждой capability.

Provider credential не записывается в шаг: сохранённый запрос содержит
placeholder, credential ID и ID выбранного физического ключа. Gateway
подставляет секрет только в назначенный запрос. На узле он живёт в памяти
в течение запроса. Загруженные файлы и крупные результаты передаются через
подписанные URL конкретных объектов; доступ к PostgreSQL/Redis/S3 secrets
удалённому узлу не выдаётся.
Production Web предоставляет только точные `/worker/v1/*` POST через
bounded same-origin proxy: проверяется формат токена и UUID, cookies/Origin
не принимаются, сырой Jobs-порт не публикуется. Jobs повторно проверяет
хеш токена и права узла; Web не становится владельцем операций.

Центральные runtime-процессы получают результаты одной общей для своих слотов
пакетной long-poll подпиской. ACK воркеру означает центральный commit receipt;
подтверждение пользовательского результата происходит после существующего
owning ingest. При исчезновении узла незапущенный шаг можно переназначить,
а неоднозначный внешний платный запрос следует согласованной ограниченной
политике owning workflow. Сам transport не повторяет платный запрос.

Откат: `REMOTE_WORK_ENABLED=false` возвращает новые шаги существующим локальным
обработчикам. Начатые удалённые шаги принимаются до их fenced receipt/timeout.
Новые таблицы и подтверждённые результаты при откате сохраняются.

Проверено 30 сентября: изолированная PostgreSQL — действующий tenant/lease,
fenced повтор ACK, физически отсутствующий узел, справедливые доли десяти
операций, административные лимиты и блокировка третьего неоднозначного
платного исполнения. Бесплатный HTTPS E2E запускает настоящий агент без
DB/Redis/S3/SMTP-секретов и проходит inspection → import → persisted SEO,
а также export → signed multipart → скачивание XLSX пользователем и
crawl → удалённый HTTP/анализ → центральный snapshot → завершение.
Провайдерские команды всех пяти capabilities проверяются на transport mock
без платных запросов. Нагрузочная ёмкость 100 съёмов не заявляется без замера.

Временные transport artifacts/receipts старше семи дней очищаются hourly
sweep только после закрытия owning workflow. Канонические экспорты имеют
собственный срок хранения и не удаляются транспортной уборкой; позиции,
частотности, операционные summaries и billing receipts не затрагиваются.

Non-HTML HTTP-ответ сохраняет самостоятельный bounded snapshot вместо
прогресса без SEO receipt. Бесплатные этапы после подтверждённого закрытия
удалённого задания могут продолжиться локально; действующий удалённый upload
не пишет один canonical export key одновременно с локальным исполнителем.
Отказ удалённого XLSX-парсера `INVALID_XLSX` также перепроверяет центральный
owning parser после закрытия remote receipt: валидный файл не теряется из-за
сбоя среды одного узла, действительно битый файл остаётся ошибочным.
У Arsenkin очистка submit marker допускается только по свежему закрытому
Gateway receipt, доказывающему отсутствие отправки. Неизвестный результат
платного вызова не превращается в свободный повтор из-за занятости узла.
