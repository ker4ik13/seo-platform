# ADR-2026-058: начальные настройки проекта без платного запуска

Дата: 8 октября 2026 года. Статус: реализация для локальной проверки.

## Решение

Утверждённый мастер состоит из трёх шагов: проект, поиск/ИИ, колонки.
Platform Core владеет immutable начальным шаблоном projects.onboarding:
двумя поисковиками, максимум 64 географическими срезами и начальным порядком
видимых колонок. Шаблон не является mutable пользовательским представлением.
Фактические tracking contexts и saved views по-прежнему принадлежат SEO Data.
Изменения личного представления не перезаписываются начальным шаблоном.

Создание Core с шаблоном требует scoped Idempotency-Key. Проект и receipt
создаются одной транзакцией под уже существующей блокировкой порядка workspace.
Потеря ответа не создаёт второй проект. Следом Core выполняет один внутренний
bounded initialize command SEO Data, который пакетно создаёт конфигурации
без keyword assignments и начальный saved view. Собственный receipt SEO Data
и project-scoped lock делают этот шаг повторяемым после сбоя. Retry не обновляет
уже существующие настройки, не создаёт дубли контекстов и не отменяет чужие
изменения. Core отмечает успешную инициализацию только после строгой проверки
ответа owning service. Новых очередей, провайдерных запросов и dependencies нет.

Shared view создаётся только для OWNER/ADMIN; SEO_LEAD получает private view,
а начальный шаблон проекта остаётся доступным как fallback новой личной таблицы.
Public command не принимает actor/owner/workspace IDs внутри onboarding.
Внутренний guard проверяет service token, route и trusted tenant/actor headers.

Регион и устройство задают identity колонки; глубина не создаёт новую колонку.
Плановые колонки отображаются до первого результата, но не создают фиктивных
снимков, нулевых позиций или бесплатных/платных операций.
Приоритет запуска: явный контекст/повтор → последний успешный выбор →
начальный шаблон → прежний безопасный default. Верхние серии графика
выключаются только как начальное предпочтение соответствующего среза.

WS (количество слов), Группа, Теги и Источник выключены в новом default.
Сохранённые пользовательские представления не мигрируются насильно.
Импорт, расширение семантики и платный съём остаются отдельными командами.

## Проверка

Shared parsers проверяют ограниченные срезы и только достижимые колонки.
PostgreSQL integration покрывает конкурентные повторы создания и bootstrap,
изоляцию actor/workspace, пустой проект и отсутствие keyword/provider работы.
HTTPS browser E2E проходит мастер, последующую таблицу, повторное открытие,
сохранение личного порядка и восстановление defaults в мастерах съёма.
