# ADR-2026-048: фиксация платной отправки rank и финансовые письма

Дата: 7 сентября 2026. Статус: принято в рамках коммерческого MVP.

## Финансовые отправки

У rank уже есть отдельный Core-owned резерв на каждый provider task. Его
истечение до сохранения ответа могло освободить реально потраченные средства.
Перед платным I/O Execution вызывает существующий HOLD: Core атомарно
фиксирует `provider_started_at`. Sweeper освобождает только неотправленные
резервы. ACCEPTED приводит к CAPTURE; подтверждённый отказ — к RELEASE;
неизвестный исход или некорректный ответ сохраняет резерв для разбора.

HOLD/CAPTURE/RELEASE доступны только через специализированный authenticated
settlement API, с проверкой grant, workspace, project, actor, price и job item.
Время отдельного внутреннего settlement-запроса ограничено 5 секундами;
submit lease учитывает два таких запроса и provider timeout внутри 25 секунд.

Admin finance queue объединяет generic usage tickets и старый rank ledger.
Для rank решение и balanced ledger/audit фиксируются одной транзакцией.
Действуют MFA, недавняя аутентификация, терминальный Jobs state, пять минут
на поздний ответ и идемпотентный ключ. Подтверждённое списание требует номера
операции провайдера. SQL не допускает очистку факта отправки, изменение
финансового решения или переписывание исторических сумм. Результат SEO не
выдумывается, запрос повторно не отправляется.

Web retry частотности и rank создаёт новый обычный wizard с текущими версиями
неудавшихся ключей, исходными параметрами и новым подтверждением цены.
Пустой scope никогда не интерпретируется как весь проект.

## Финансовые письма

Core владеет неизменяемым intent `billing_notices` и outbox. Существующий
изолированный auth-email worker получает новый event type
`billing.notice.requested.v1` и выполняет SMTP. Дополнительной очереди нет.
События содержат только notice/workspace ID; recipient, названия и суммы
разрешаются Core через private material API непосредственно перед отправкой.
Проверяются текущая роль получателя, lifecycle, реальный платёж, актуальный
статус возврата и неизменность периода подписки. Новое продление делает старое
напоминание недоставляемым. Тестовые оплаты не порождают финансовые письма.

Планировщик догоняет события за 7 дней, выбирает не более 100 за проход и
использует уникальный business key/advisory lock. SMTP сохраняет существующие
retry, leases и постоянный Message-ID. Не обещается невозможная exactly-once
доставка SMTP при аварии после принятия сообщения почтовым сервером.

## Миграция и откат

Только новые таблица/поля/checks/indexes и расширение allowlist событий.
Исторические financial rows, пользователи и проекты сохраняются. NATS topology
и publisher ACL обновляются перед readiness новых процессов. Rollback допускается
на совместимый artifact: старый sweeper без знания provider_started_at нельзя
запускать с новыми RESERVED строками. Platform-paid flags выключаются до смены
протокола; существующие финансовые записи не удаляются для отката.

Provider account limits не заменяются техническими ceilings: публично Arsenkin
указывает 30k/70k для Standard/Corporate. Конфигурация
`PLATFORM_ARSENKIN_CLUSTERING_KEYWORD_LIMIT` проверяется до резерва; увеличивается
только после подтверждения аккаунта. Источник:
[Arsenkin — тарифы](https://arsenkin.ru/tools/tariffs/all/).
