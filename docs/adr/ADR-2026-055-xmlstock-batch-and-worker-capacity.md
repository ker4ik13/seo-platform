# ADR-2026-055: пакетные XMLStock-операции и источник ёмкости узла

- Статус: реализовано в ветке `codex/worker-fleet-db-pilot`; production cutover после проверки.
- Дата: 1 октября 2026 года.
- Дополняет ADR-2026-050/051/052/054; владельцы данных не меняются.

## Решение

XMLStock rank submit/poll читает до 100 ID кандидатов одной короткой SQL
выборкой. Кандидат не даёт права на платный запрос: каждая страница получает
атомарный version-fenced lease. Gateway продолжает ограниченно сканировать
кандидатов, если один физический ключ или product занят; это оставляет
свободные HTTP-слоты Google XML, Яндекс XML и других ключей доступными.
Внутри страницы poll кандидаты чередуются по продукту до применения LIMIT,
чтобы старая большая очередь Live не вытеснила Google/XML из ста ID.

Частотность/сезонность XMLStock закрепляет до 50 фраз на Job за один claim,
разрешает их через один Core SEO batch и выполняет пять волн максимум по
10 фраз. Каждый вызов получает Redis permit по физическому ключу и product;
этот permit делится между workspace и всеми узлами. Разные ключи занимают
независимые product buckets, пока хватает слотов узлов. После каждой волны
подтверждённые ответы сохраняются пачкой в Core SEO, а Jobs одной fenced
функцией отмечает успех/ошибку/ожидание ёмкости и обновляет прогресс. Lease
продлевается между волнами; поздний или отменённый worker не может закрепить
результат. Arsenkin сохраняет свой provider batch-контракт.

Для нового узла `uses_env_capacity=true`: heartbeat сообщает `WORKER_*`, и
центр обновляет базовые лимиты. Ручная настройка переводит узел в
`uses_env_capacity=false`: административные HTTP/CPU/capability limits
становятся итоговыми после следующего heartbeat. Агент получает их в ответе
и применяет без изменения своего `.env`; report продолжает показывать исходные
значения. Старые узлы мигрируют в ручной режим. Токен после ротации немедленно
отзывает старый. При `401` агент прекращает запрашивать работу и раз в
30 секунд проверяет восстановление связи, не завершая процесс. Админка
показывает только короткий отпечаток хеша; введённый для сверки токен
хешируется в браузере и не передаётся серверу.

## Откат и проверка

Выданная работа остаётся под прежними leases и идемпотентными receipts.
Откат worker capacity: вернуть узел в режим `.env` в админке. Откат XMLStock
runtime требует предыдущего image; подтверждённые строки и ledger остаются.
Проверки: изолированная PostgreSQL, тест 50 фраз/10 одновременных, смешанные
outcomes, три XMLStock rank products, ротация токена и capacity через публичный
HTTPS/Caddy без платных вызовов.
