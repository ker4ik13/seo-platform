# ADR-2026-053: закрепление rank poll за исполнителем

- Статус: принято для существующего удалённого XMLStock rank poll.
- Дата: 30 сентября 2026 года.
- Владение данными не меняется: назначения и leases принадлежат Jobs.

## Причина и решение

Локальные connector lanes и удалённый агент конкурировали за одни страницы.
Операция могла отображаться одновременно на main и remote, а кандидатные
окна одного Gateway процесса мешали разным узлам.

`rank_job_worker_assignments` хранит одно назначение Job. Выбор нового узла
учитывает здоровую мощность и число активных назначений. После назначения
занятость узла не позволяет main перехватывать страницы: слоты делятся внутри
назначенного узла. Управление и сохранение остаются централизованными.
Назначение сериализуется короткой advisory-lock только при его создании или
замене; HTTP не выполняется внутри транзакции. Обычный lookup indexed.

Prefetch вычисляет владельца раз на активный Job, затем выбирает до 30 ID.
Окна ID разделены по исполнителю. Atomic targeted claim повторно проверяет
владельца, поэтому старая подсказка не даёт права выполнить платный запрос.
Существующие physical-key/product permits, fairness и fencing сохраняются.

При disable/drain, нулевой capacity или отсутствии heartbeat 30 секунд новый
claim уходит другому здоровому узлу, а без него main. Уже выданная страница
не дублируется до окончания её lease: прежний исполнитель ещё может передать
результат. После expiry действует существующий bounded recovery, включая
ограничение повторной потенциальной оплаты. Подтверждённые snapshots не удаляются.

## Границы и эксплуатация

Это исправление существующего remote poll, а не перенос всех execution roles.
Подготовка, submit (включая delayed Search API) и ingest пока выполняются в
центре. Для переноса submit нужен отдельный wire protocol и отказные проверки
30-секундного grant. SMTP остаётся в центре. Это не доказательство линейного
масштабирования всей платформы.

Admin читает safe-проекцию назначения даже между активными HTTP-запросами.
Worker Gateway при выключенном feature flag не обновляет heartbeat.
Новая SQL-функция выдаётся только connector и opt-in HTTP/BOTH ролям;
таблица не доступна браузеру или удалённому агенту.

## Проверка и откат

Изолированный PostgreSQL: main не получает страницы назначенного Job;
busy node не теряет назначение; disable/offline переключает исполнителя;
lease fencing сохраняется. Контракт нулевого `activeTasks` проходит strict
consumer. Для отключения remote используются admin disable/drain; через
30 секунд без heartbeat main возобновит выдачу. Таблица не хранит результаты
и может остаться при rollback приложения.
