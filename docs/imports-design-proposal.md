# Дизайн переноса проектов и импорта данных

Статус: дизайн согласован; файловая история позиций реализована на локальном
стенде для CSV, TSV и XLSX. WIDE/LONG, привязка отдельных URL, редактирование
назначений и географии используют существующий worker pipeline. Пуша нет.
Перенос проектов через внешние API, XLS и выбор нескольких листов остаются
отдельными последующими этапами, не заявляются как работающий функционал.

Один мастер покрывает готовый проект, запросы с колонками и историю позиций.
Пользователь выбирает источник, проверяет сопоставление колонок и параметры
снимков, затем видит точный перечень изменений перед запуском. Отдельный
вариант предназначен для переноса нескольких проектов через API.

## Источники первой версии

| Источник | Файлы и структура | Подключение для переноса |
|---|---|---|
| Topvisor | CSV/XLSX; дополнительные поля, URL рядом с датой или в компактной ячейке; несколько регионов могут быть на отдельных листах | API v2: User ID и API-ключ; читать проекты, группы, запросы, выбранную историю |
| Key Collector | Нативный KC4; CSV/XLSX с изменяемыми разделителями, колонкой группы, картой листов и расширенной статистикой | Файл проекта или экспорт; не предлагать несуществующий вход по паролю |
| SE Ranking | CSV/XLS, выбранный период и поисковая система; исторические отчёты | Project API; доступность и лимиты проверяются для конкретного аккаунта |
| Rush Analytics | XLSX/CSV таблиц; файл может отражать фильтры и выбранные колонки | В первой версии файловый перенос |
| Другая таблица | CSV/TSV/XLSX; ручное сопоставление и сохранённый шаблон | Файл |

Профиль сервиса — подсказка для распознавания, а не повод пропускать проверку.
Topvisor документирует разные способы упаковки URL и листов регионов;
универсальный фиксированный набор заголовков здесь недостаточен.
[Экспорт Topvisor](https://topvisor.com/ru/support/rankings/export/).
У Key Collector настройка экспорта меняет путь группы, CSV-разделители,
объединение ячеек и служебные листы; их нужно различать в предпросмотре.
[Настройки экспорта Key Collector](https://www.key-collector.ru/docs/preferences/export/),
[формат проекта KC4](https://www.key-collector.ru/docs/projects/).
SE Ranking описывает экспорт истории CSV/XLS по выбранному периоду.
[Экспорт SE Ranking](https://help.seranking.com/hc/en-us/articles/16332593981468-How-to-work-with-the-Rankings-data).
Rush Analytics подтверждает XLSX/CSV и настройку выгружаемых таблиц.
[Экспорт Rush Analytics](https://www.rush-analytics.ru/faq/analiz-poziczij/polnyj-gajd-po-gostevoj-ssylke-rush-analytics-proverka-poziczij).

Для файлов AllPositions и остальных сервисов сначала используется общий
мастер; отдельный готовый профиль добавляется после проверки настоящего
экспорта. Не обещать API-адаптер без подтверждённого актуального контракта.

## Мастер одного импорта

Четыре шага: «Источник», «Колонки», «Настройки», «Проверка». Header, шаги и
footer не меняют ширину от содержимого; широкая таблица имеет свой scroll.
На телефоне поля располагаются последовательно; действия остаются доступны.

### Источник

- Цель: готовый проект / запросы с колонками / история позиций.
- Сервис и способ переноса: файл или документированное API.
- Назначение: новый проект или существующий доступный проект этой области.
- При новом проекте: домен и пользовательское название; распознанные
  значения можно исправить. Название после этого не заменяется автоматически.
- При совпадении домена показать выбор проекта назначения. Не менять чужой
  проект и не создавать дубликат без явного выбора.
- Выбор листов Excel; карта навигации и справочные листы не становятся
  запросами. У выбранных листов отдельные понятные параметры снимков.

### Колонки и история

| Формат истории | Сопоставление | URL из поисковой выдачи |
|---|---|---|
| Дата в каждой колонке | Колонка → дата + поисковик + город + устройство + позиция | Связать URL с той же датой; поддержать парную колонку и документированный компактный вариант сервиса |
| Дата в каждой строке | Колонки запроса, даты, поисковика, города, устройства и позиции | Отдельная колонка найденного URL этой строки |
| Один снимок | Запрос и позиция; общие дата и география, если их нет в строке | Отдельная колонка найденного URL |

Целевой URL и найденный URL — разные поля, не заменяющие друг друга.
Яндекс и Google за одинаковый день сохраняются отдельно, но отображаются
рядом в истории по одной географии и устройству. Привязку между колонками
показывать в самом заголовке: исходное имя, назначение, дата и бренд-логотип.

Нужны явные назначения: запрос, язык, группа, теги, целевой URL, частотности,
позиции, найденные URL, дата, своя типизированная колонка и «не импортировать».
Обязательные поля нельзя убрать без отображаемой ошибки. Если заголовок не
содержит географию, предложить настройки проекта и запросить подтверждение;
не угадывать город по числу позиции или имени файла.

Именованный контекст необязателен. География снимка обязательна. Выбор
существующего контекста не переименовывает его и не изменяет конфигурацию.
Для даты без времени сохраняется точность «день»; интерфейс не должен
выдавать придуманные часы за действительное время съёма.

Различать четыре значения: отсутствующий замер, «не найдено», числовая
позиция и явное «за пределами ТОПа». Пустую ячейку нельзя превращать в ноль
или новую позицию; обозначение `--` Topvisor означает отсутствие найденной
позиции, а не потерянную строку. Семантика чисел и маркеров определяется
профилем и подтверждённой привязкой.
[История позиций Topvisor API](https://topvisor.com/ru/api/positions-2/get-history/).

### Правила изменения данных

- По умолчанию обновляются только явно выбранные поля; история дополняется.
- Дополнительные режимы: сохранить существующие значения / добавить только
  отсутствующие запросы. Сопоставление включает нормализованный текст и язык.
- Пустые значения по умолчанию не очищают данные проекта. Очистка — отдельный
  явный выбор с подтверждением последствий.
- Группы сохраняют дерево и не плодят одинаковые ветви при повторе.
- Свои колонки: имя, тип и пример значения; конфликт типа решается до запуска.
- Представление семантики формируется из выбранных колонок и срезов.
  Пользовательские настройки существующего проекта не сбрасываются.
- Расписания и платные сборы из чужого проекта не запускаются автоматически.

### Проверка перед запуском

Показать количества новых/обновляемых запросов, групп, колонок и снимков,
период и географии; отдельно — конфликтующие и пропущенные строки. Для каждой
ошибки доступны файл, лист, строка, колонка, причина и действие исправления.
Можно вернуться к привязкам или явно импортировать только проверенные строки.
Подтверждение связано с hash файла и mapping revision, чтобы изменения после
проверки не запускались по старому результату.

## Перенос проектов через API

После подключения выбираются проекты источника, период истории и состав
переноса. Для каждого проекта видны назначение, объём и индивидуальные
проблемы. Ошибка одного проекта не отменяет остальные. Прогресс показывается
в общем журнале и отдельно по проектам; окно можно закрыть после запуска.

Topvisor использует User ID и Bearer API key. Адаптеру достаточно разрешить
только чтение; оператор `get` в этом API передаётся HTTP POST, что нельзя
путать с платной командой запуска съёма.
[Авторизация Topvisor](https://topvisor.com/ru/api/v2/first-call/).
SE Ranking имеет Project API для проектов, групп и истории, но его ключ
нельзя считать ограниченным только чтением на стороне провайдера. Наша
сторона должна иметь allowlist read-методов и показать стоимость/лимиты до
большого переноса; логин и пароль аккаунта для этого не нужны.
[Project API SE Ranking](https://help.seranking.com/hc/en-us/articles/21850333996956-Set-up-the-SE-Ranking-Project-API-on-Make),
[ограничения API-ключей](https://help.seranking.com/hc/en-us/articles/26182120787740-SE-Ranking-s-API-FAQ).

Ключ вводится через защищённую форму и живёт только в vault/opaque reference.
Он не попадает в URL, queue payload, ошибки или сохранённый draft браузера.
Реальный provider read smoke — только с согласованным объёмом и бюджетом.

## Состояния экранов

Выбор файла, загрузка, антивирусная проверка, разбор структуры, готовый
предпросмотр, неоднозначные колонки, неизвестная география, ошибки строк,
отклонённый ключ, недоступное API, ограничение плана, отсутствующие права,
проверка перед запуском, публикация, запрос отмены, полный результат и
частичный результат должны различаться. При повторе сохраняются валидные
настройки; ошибки не маскируются бесконечной «подготовкой».

Загрузка возобновляется своим протоколом. После получения файла durable Job
продолжается после перезапуска worker по checkpoint. Перезапуск не
перепубликует подтверждённую пачку и не создаёт повторные снимки.

## Производительность и безопасность будущей реализации

Расширять существующий import pipeline, а не создавать отдельный механизм
для каждого сервиса. Общий результат reader — нормализованные bounded batches.
Внешнее чтение, антивирус, разбор и публикация остаются Execution work;
Core владеет проектом/доступом, SEO — опубликованными данными.

Предпросмотр читает ограниченный sample и пагинацию. Большой файл не
переносится полностью в браузер или одну транзакцию. Существующие manifest
ограничения требуют физических publish-пачек не более 500 записей; повтор
подтверждается receipts. Parent counts считаются отдельно от каждой страницы.

XLS и компактные Excel-URL требуют проверки реальных файлов и выбора
безопасного parser. Новую production-зависимость согласовать отдельно.
Архивы, внешние ссылки, макросы, формулы, исполняемое содержимое и размеры
проверяются до публикации; небезопасный файл блокируется, недоступность
антивируса не означает разрешение импорта. Secrets колонок не отображать
в ошибках и диагностическом журнале.

## Приёмка после согласования

Нужны настоящие обезличенные экспорты каждого выбранного сервиса: обычные,
мультигруппы, несколько листов, обе схемы дат, разные поисковики/географии,
найденный и целевой URL, отсутствие замера и «не найдено». Golden-файлы
сопоставляются с ожидаемыми persisted snapshots, а не с подменённым API.

HTTPS E2E проходит выбор файла → mapping → validation → worker → owning
publisher → PostgreSQL → семантика/история. Отдельно проверить повтор,
потерянный ответ, отмену, перезапуск worker, недоступность антивируса и
границы доступа. Нагрузочные тесты фиксируют число DB/HTTP обращений,
время первого предпросмотра, throughput, DOM и память на больших файлах.

Файловые WIDE/LONG CSV/TSV/XLSX проверяются настоящими загрузками через HTTPS,
ClamAV и import worker, с независимой проверкой сохранённых дат/позиций/URL.
Неправильная дата исключает строку; тесты не подменяют API/SQL-ответы.
API-адаптеры проектов и неподдерживаемые форматы пока не выкатываются. Для них
экраны остаются макетами. На согласование
передаются снимки, не встроенный интерактивный виджет. Сопоставление колонок
показано Excel-подобной сеткой: буквы столбцов, номера строк, видимые границы
ячеек, закреплённый запрос и отдельный scroll таблицы. Для каждой даты можно
сопоставить позицию и найденный URL; построчный вариант отдельно показывает
дату, поисковик, город и устройство.
